# Felt Club · 德州扑克

Next.js + Tailwind CSS + HTML5 Canvas 的多人德州扑克房间。2–6 位已注册玩家可组成私人牌桌；SQLite 保存昵称、可选头像、邀请、房间和已结束牌局。

## 启动

```bash
npm install
npm run dev
```

打开 `http://localhost:3000`。让其他玩家访问同一服务器地址并注册昵称，即可互相邀请。需要给局域网或公网玩家使用时，请将 Next.js 服务部署到他们都能访问的服务器上。

## 数据保存与备份

数据库默认位于 `.data/poker.sqlite`，也可通过 `POKER_DB_PATH` 指定绝对路径。请把该路径放在持久化、可写的本地磁盘上；使用单台服务主机，不要让多台主机共享同一 SQLite 文件。启动时会按 `PRAGMA user_version` 执行数据库迁移，较新版本的数据库不会被旧程序打开。

运行 `npm run backup` 可在线生成一致的 SQLite 备份，默认保存在数据库旁的 `backups/` 目录；也可以运行 `npm run backup -- /path/to/backup.sqlite` 指定目标。重要备份应另存到其他设备。恢复时先停止服务，把原数据库及同名 `-wal`、`-shm` 文件一起移到其他目录留存，确认数据库路径没有旧的 `-wal`、`-shm` 文件，再将备份复制到数据库路径并启动服务。

`npm run typecheck` 可单独检查 TypeScript 类型。

## 实时同步与部署

`npm run dev` 和 `npm start` 都由 `server.ts` 启动同一个 Node.js 进程，同时处理 Next.js 页面、HTTP API 和 `/realtime` WebSocket。生产启动前执行 `npm run build`，可用 `npm start -- --hostname 127.0.0.1 --port 3000` 指定监听地址。反向代理需允许 `/realtime` 的 WebSocket Upgrade；现有 Cloudflare Tunnel 可沿用同一域名和端口。

牌桌通过 WS 建立身份认证和 WebRTC 信令连接。玩家操作先由服务器校验、推进游戏并写入 SQLite；公共状态附上 ECDSA P-256 签名后交给一名在线玩家，通过 WebRTC DataChannel 转发。每位玩家的暗牌、可执行操作和私人邀请只经其自己的 WS 连接发送。客户端核验签名、房间、服务实例和状态版本后，才合并同版本的公共与私人状态；客户端不能提交任意筹码或整份牌局覆盖服务器。

正在游戏时没有房间 HTTP 轮询。加入或重连时经 WS 接收快照，此后仅在变化时推送，20 秒的心跳用于发现断线。浏览器直连失败时使用同一条 WS 补发；若转发后 1 秒仍未收到确认，服务器补发当前状态。重复操作编号会被去重，旧版本操作会被拒绝；断线期间不自动重试下注，重连后以已保存的牌局为准。服务器重启后会重新发放验证公钥并恢复 SQLite 中的状态。

公网页面需使用 HTTPS，以启用浏览器 Web Crypto 和 WebRTC。默认使用 Cloudflare 公共 STUN (`stun:stun.cloudflare.com:3478`)；可用环境变量 `POKER_ICE_SERVERS` 配置 JSON 格式的 `RTCIceServer[]`。没有配置 TURN 时，无法穿透的网络直接退回 WS，不要求额外部署中转进程。跨网络直连成功率取决于玩家网络，不能保证所有玩家都绕过服务器传输公共状态。

新进程内每 15 秒执行房间关闭超时检查。部署后停用旧的 `texasholdem-close-expired.timer`，避免外部定时任务与实时通知重复运行。`npm run close-expired-rooms` 可手动执行一次同一项检查。账户、邀请、历史等 HTTP API 继续使用；原房间 HTTP API 保留兼容已有页面，新牌桌前端通过 WS 进行房间操作。

`npm run test:realtime` 使用临时 SQLite 和随机端口，验证暗牌隔离、签名、重连、转发补发、操作去重、旧版本拒绝及历史保存，不访问生产数据库。

卡牌 SVG 使用浏览器及 CDN 一年缓存；更新 SVG 时需同步递增 `app/table-canvas.tsx` 中的 `cards-1` URL 版本标记。

## 已实现

- 昵称注册（必填）、头像（选填）与已有昵称登录；玩家在线状态和昵称列表。当前按昵称识别身份，不设置密码。
- 私人房间邀请与站内通知；接受邀请后进入等待大厅，2–6 人开始游戏。房主可设置人数上限、1–4 副牌、小盲、大盲、初始筹码、前注和按手数翻倍的盲注升级。
- 多人行动顺序、盲注轮换、下注轮闭合、弃牌、过牌、跟注、加注与全下。
- 牌型比较、踢脚牌、A-2-3-4-5 顺子、平局和全下边池结算。多副牌是自定义玩法，允许重复牌面，并以五条为最高牌型。
- 默认盲注为小盲 25 / 大盲 50，默认每位玩家初始 1,000 点；筹码耗尽后暂时淘汰，房主可在两手之间补充指定玩家的筹码；只剩一位有筹码的玩家时显示赢家。可在原房间直接开始下一对局，玩家按房间设置重新获得初始筹码。盲注升级按当前对局的手数计算，重新开局后重置。
- 房主可在两手之间修改下手的牌桌规则、邀请新玩家、移出玩家和补充筹码；进行中的一手不会被改动。修改后继续投票重置，所有在场且有筹码的玩家重新确认。初始筹码设置影响新加入玩家和下一场对局，当前玩家筹码不自动重置。
- SQLite 持久化房间及进行中的牌局；刷新页面后可回到原房间。
- 玩家申请退出后，发起人自动计一票；任意两名成员同意即可立即关闭房间。若未达到两票且无人取消申请，5 分钟后自动关闭。任一成员可在超时前取消申请。自动关闭会删除房间及其牌局历史，保留玩家账号。服务进程每 15 秒检查关闭超时，并通知在线玩家；页面请求也会顺手清理已到期房间。
- 游戏界面铺满屏幕，只保留牌桌、行动、筹码与房间控制。
